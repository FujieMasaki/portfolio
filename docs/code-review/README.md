# AIコードレビュー指針

このポートフォリオサイト（Next.js App Router / React）のコードレビューにおける運用ルールと観点を定義する。
サイトの世界観とデザインの判断基準の正本は`CLAUDE.md`であり、この文書には複製しない。レビュー品質を
継続的に改善するため、このディレクトリは生きたドキュメントとして扱う。

## 1. 運用

- レビューは原則として全差分を対象にする。差分だけで判断できない場合は、関連する
  コンポーネント、hook、型、設定、画像も確認する。
- レビュー開始時に必ず [`security.md`](./security.md) を読む。セキュリティは最重要
  観点である。
- UI・体験・デザインの変更では、`CLAUDE.md`の「このサイトの前提」「避けるもの」と照らし合わせる。
- 指摘には重大度、該当ファイル・行、根拠、影響、具体的な修正案を付ける。十分な根拠を
  得られないものは「要確認」とし、事実と推測を区別する。
- Critical、High、Medium の指摘がなければ `LGTM` と明記する。無理に改善案を
  捻出しない。
- ローカルで依頼されたレビューはチャットへ出力する。ユーザーの明示的な依頼なしに、
  プルリクエストへの投稿や承認は行わない。
- 見落としや継続的な誤検知が判明したら、この README または該当観点ファイルを
  更新する。

## 2. 重大度

| 重大度 | 定義 | 対応 |
| --- | --- | --- |
| 🔴 Critical | 秘密情報の漏洩、訪問者の情報の意図しない外部送信、サイトが表示されない | マージ前に必ず対応 |
| 🟠 High | 悪用または重大な不具合（特定の端末・ブラウザで表示が崩れる・固まる、操作できない）につながる可能性が高い | 原則マージ前に対応 |
| 🟡 Medium | 限定的な影響、保守性、アクセシビリティ・性能の不足、`CLAUDE.md`の「避けるもの」に当たる | 対応を推奨 |
| 🔵 Low | 軽微な改善提案 | 任意 |

## 3. 変更種別ごとの確認

| 変更内容 | 最低限確認する観点 |
| --- | --- |
| すべての変更 | `security.md` |
| 動き（CSS animation・transition、`useFrame`、scroll連動） | `prefers-reduced-motion`で止まる・弱まるか。JSで止める動きは、表示した時点の1回だけでなく、閲覧中に設定が変わっても追従するか（`matchMedia`の`change`を購読しているか）。常に何かが動いていないか。CSSで止める指定（`@media (prefers-reduced-motion: reduce)`の中）が、hover・フォーカス時の動きの指定（`.a:hover .b`等）より詳細度が低く、負けていないか。動きの量が`CLAUDE.md`の「避けるもの」（大きなカメラ移動、激しいscroll連動、強いBloom等）に当たらないか |
| Three.js / React Three Fiber | geometry・material・textureを作った側が破棄しているか（unmount・再生成でGPUメモリが増え続けないか）。描画ループが不要なときに止まるか（`frameloop`、画面外・タブ非表示）。color space・tone mappingの設定。WebGLが使えない・context lossのときにDOMの表示だけで成り立つか。詳しい監査は`developing-threejs-apps` skill |
| 画像・動画・フォントの追加 | 表示サイズに対して大きすぎないか（`next/image`のサイズ指定、形式）。LCPに当たる画像の読み込み優先度。`alt`。不要になった素材が残っていないか |
| レイアウト・タイポグラフィ | スマホ幅（360px前後）で横スクロールや重なりが出ないか。文字の大きさ・行間・コントラスト |
| 操作できる要素（リンク・ボタン・メニュー） | キーボードで操作でき、フォーカスが見えるか（`outline: none`にするなら、強制カラーモードでも見える代わりがあるか）。`:hover`で内容を出す演出は`@media (hover: hover)`に限っているか（タッチ端末で1回目のタップがhover表示で止まったり、戻ったときにhoverの見た目が残ったりしないか）。hoverで開く表示（メニュー等）は、クリックで開く場合と同じstateで持ち、`aria-expanded`が表示と一致し、マウスが乗ったままでもEscapeで閉じられるか（CSSの`:hover`だけで開くと、Escapeで閉じられない）。キーボードで中を操作している間に、マウスが離れただけで閉じないか。Escapeで閉じたとき、ほかの場所にあるフォーカスを奪わないか。押せない状態のボタンを`disabled`にして、押した直後にフォーカスを見失わないか（`aria-disabled`で代える）。`button`と`a`の使い分け。外部リンクの`rel` |
| ドラッグ・pointerの操作 | 要素の外でボタンを離したときや、pointer captureを失ったときに、ドラッグの状態が残らないか（`event.buttons`の確認、`lostpointercapture`の後始末）。縦のホイールを横の移動に使う場合は、その要素の上にあり、要素がほぼ画面に入っている間だけにし、先頭・末尾ではページの縦スクロールに戻しているか（ページ全体を奪わない。縦にスクロールしている途中から切り替えない）。なめらかに寄せる場合、端の判定を向かう位置ではなく実際の表示位置で行い、寄せている途中にページへ渡して縦と横が同時に動かないか（要素の外で回したホイールや、ズーム・端などでブラウザに任せるときも、寄せている途中の動きを止めているか。ボタンなどで始めたブラウザの smooth scroll も、同じ処理で止まるか）。トラックパッドの横の操作・Shift + ホイール・ピンチのズームはブラウザに任せているか。タッチはブラウザのスクロールに任せているか。同じ操作がキーボードでもできるか。スクロールバーの代わりに位置を示す表示（線の上の光など）を置く場合、展示の幅や間隔がそろわないときや、先頭・末尾に余白があって端の展示を中央に置けないときも、いま見ている展示と表示が一致するか（スクロールした量の割合だけで決めていないか） |
| client componentの追加（`"use client"`） | serverで足りるものをclientにしていないか。bundleに重いライブラリ（three等）を読み込む範囲が広がっていないか（`dynamic` importで必要な画面だけに限るか） |
| 計測・外部スクリプト（GTM等） | `security.md` §2 |
| `.env*`、`next.config.ts`、依存、CI、`.claude/`・`scripts/`の変更 | 秘密情報、公開設定、サプライチェーン、権限。人が見ていない間に動く自動化（`scripts/`・`.claude/`のskill）は、失敗・ハング時の後始末と、誰でも決められる値（fork PRのbranch名等）を信頼していないか |

## 4. レビュー出力

各指摘は次の形式を使う。

```text
🔴 [タイトル]
場所: components/path/file.tsx:12
根拠: 仕様または実装上確認できる事実。
影響: 起こり得る訪問者・表示・性能への影響。
修正案: 実装可能な修正方法。
区分: 修正が必要 / 任意改善 / 要確認（前提: ...）
確信度: 高 / 中 / 低（低い場合は確認すべき前提も書く）
```

良い点はレビュー全体の短いサマリにのみ記載し、修正を要する指摘と混在させない。

## 5. メンテナンス履歴

- 2026-10-11: 初版作成。fod-appのレビュー指針（`docs/code-review/frontend/`）を基に、静的なポートフォリオサイト
  （Next.js、Three.js / R3Fの導入予定）向けに観点を置き換えた。
- 2026-10-11: TOPヒーローのPR（#20）のレビューで、次の3点が段階を越えて繰り返し指摘されたため、§3に追記した。
  - JSで止める動きが、閲覧中の`prefers-reduced-motion`の変更に追従していなかった（Codexが再現）。
  - `:hover`による演出がタッチ端末にも効き、iOS Safariで1回目のタップが止まるおそれがあった。
  - フォーカスの線を消した状態で、強制カラーモードではフォーカスがまったく見えなかった。
- 2026-10-12: /aboutのPR（#22）のレビューで、次の点がサブエージェント・Codexの段階で繰り返し指摘されたため、§3に追記した。
  - CSSの`:hover`だけで開くメニューを、Escapeで閉じられず、`aria-expanded`も表示と食い違っていた（Codex）。stateにまとめた後も、キーボードで操作中にマウスが離れると閉じる、Escapeでほかの場所のフォーカスを奪う、という問題が続いた。
  - `prefers-reduced-motion`で止める指定が、hover時の浮きの指定より詳細度が低く、動きが止まりきっていなかった。
  - 横に流れる展示のドラッグで、要素の外でボタンを離すとドラッグの状態が残り、ボタンを押していないのに列が動いた。
- 2026-10-12: 同じPRで、Careerの横の展示を縦のホイールでも進められるようにする方針を人間が決めたため、§3の「ドラッグ・pointerの操作」には、縦のホイールを禁じる項ではなく、その使い方（要素の上にある間だけ使い、先頭・末尾でページの縦スクロールに戻す）を確かめる項を置いた。
- 2026-10-12: 同じPRで、縦のホイールの横取りについて、サブエージェント・Codexが「列が一部しか見えていないうちに切り替わる」「縦のスクロールの途中から切り替わる」「向かう位置で端を判定して、寄せている途中に縦と横が同時に動く」を順に指摘したため、§3の確かめ方に足した。
- 2026-10-12: 同じPRで、Codexが「要素の外でページを縦にスクロールし始めても、なめらかに寄せる横の動きが続く」と指摘したため、§3の確かめ方に、ブラウザに任せるすべての経路で寄せを止めることを足した。
- 2026-10-12: 同じPRで、Codexが「← → で始めた smooth scroll は、ホイールの寄せを止める処理の対象外で、途中でページに任せても横の動きが続く」と指摘したため、§3の同じ項に、ボタンで始めた smooth scroll も止まるかを足した。
- 2026-10-12: 同じPRで、Careerの末尾に最後の展示を中央に置く余白を足したあと、線の上の光の位置を「スクロールした量の割合」で決めていたため、中央の展示と光の区画が合わなくなっていた（人間が見つけた）。§3の「ドラッグ・pointerの操作」に、位置を示す表示が実際に見ている展示と一致するかを足した。
